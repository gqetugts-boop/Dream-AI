# 半合成提示词 · 结构说明

> 这份文档回答一个问题：**这五份提示词看起来有很多重复，能不能合并整理？**
> 结论：**不能。那些重复是刻意的。**
> 以后再有人（包括我自己）想「整理一下结构」，先看这里。

---

## 一、五份提示词的共同架构

```
标题 / 最高守则
  ↓
【强制门禁】      二选一判断：适合 → 走完整流程；不适合 → 输出黑底白字说明
  ↓
【与换背景的根本区别】  画出任务边界
  ↓
【N 个输入框】     本任务的可填参数，各自独立、留空则自动判定
  ↓
【任务元素】       地面效果 / 地面道具 / 浮空元素 / 背后装饰层 / 悬空环绕 …
  ↓
【道具密度控制】   按档位执行
  ↓
【比例锚定】       以人物身体为量尺
  ↓
【透视匹配】       水平 / 垂直 / 俯仰 三维对齐 + 自检清单 + 严禁清单
  ↓
【材质与画风统一】  至高红线
  ↓
【光影融合】       只做投影与接触阴影
  ↓
【必须保留 — 红线】  ★ 汇总强调
  ↓
【失败判定】       ★ 收尾自检清单
  ↓
【至高红线】       一段式总结
```

各份的差异只在「任务元素」那一段（做地面 / 做地台 / 只做悬空 / 半身空间），
其余骨架一致。

---

## 二、为什么「重复」不能合并

扫描后发现，关键约束普遍出现在 **2–4 个位置**。但它不是散落，是**三段式**：

| 位置 | 作用 |
|---|---|
| **定义处**（如【光影融合】） | 说清楚规则本身 |
| **【必须保留 — 红线】** | 汇总再压一遍 —— 对抗长提示词中后段的注意力衰减 |
| **【失败判定】** | 列成「出现 X 就重做」的**收尾自检清单** |

以「不重打人物光」为例，它在四份里都同时出现在定义处、必须保留、失败判定。
**这三处的措辞和作用各不相同**，合并成一处会：

- 丢掉「收尾时逐条自检」这个机制（自检清单必须在末尾才起作用）
- 丢掉「在任务元素处就地提醒」（模型在生成那个元素时看不到末尾的清单）

**所以这五份提示词在「内容一字不改」的前提下，没有可做的结构整理。**
唯一能整理的地方，恰恰就是功能本身。

## 三、真正做过的一致性检查（2026-09）

| 检查项 | 结果 |
|---|---|
| 章节顺序 | 五份一致 |
| 分隔线 | 统一 30 宽 |
| 连续空行 / 行尾空白 | 零 |
| 列表符号 | 统一 `- `，无混用 |
| 跨份共享的样板句 | 10 条，**刻意共享**（每份都要能独立使用） |
| 章节标题措辞 | 门禁 / 换背景 / 输入框 / 密度 / 材质 / 必须保留 / 失败判定 —— 已统一 |
| **标题层级** | **唯一的不一致**：只有 `semiPlain` 有 `# 一级标题`，其余四份没有 |

关于标题层级：补齐需要**新增文字**（而 `label` 字段是界面用的
「半合成(无垂悬)」，不是文档标题，拿来当 H1 等于编词），
删掉 semiPlain 的又丢信息。所以维持现状。

## 四、如果确实要动，只有两条路

| | 代价 |
|---|---|
| **精简压缩** | 合并重复表述、收紧冗长解释，**一条约束不删**。目标砍 20–40%。这是唯一能实质改善的路，但会改到措辞 |
| **统一小标题** | 标题本身带信息（「关键」是强调、「（水平+垂直+俯仰）」是内容索引），统一就会丢或加信息，**是真的会动到行为** |

两条都需要你明确点头 —— 因为它们都违反「内容一字不改」。

## 五、改提示词的正确流程

```bash
# 1. 改母本（唯一该手改的地方）
vim _dev/prompt-sources/tile-hemisynth.prompts.plain.js

# 2. 重新生成混淆版（内含自检：往返不一致会拒绝写盘）
node _dev/prompt-sources/build-hemi-prompts.js
```

**不要直接改** `src/features/reference-ui/tile-hemisynth.prompts.js` ——
下次构建会整份覆盖。

母本正文用模板字符串包裹，**别在里面写反引号、`${` 或反斜杠**，
会在读取母本时就炸掉（构建脚本有检查，但早点知道省事）。

## 六、背景：这条工具链曾经是断的

混淆版的文件头一直写着「母本在 `_dev/prompt-sources/`，
改完运行 `build-hemi-prompts.js` 重新生成」—— 但**那个目录和脚本都不存在**。
等于这份提示词实际上没法改。

2026-09 已补回：母本从当时的混淆版解码还原，构建脚本重写（含往返自检），
并逐字比对确认与原文件完全等价。
